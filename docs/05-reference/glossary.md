# Glossary — OpenBA Framework Terminology

| Term | Definition |
|---|---|
| **Acceptance Criteria (AC)** | Conditions that must be satisfied for a PBI to be considered complete. Written in Gherkin format (Given/When/Then). |
| **Artifact** | Any managed document in OpenBA: Need, Requirement, Feature, or PBI. |
| **AS-IS Double Pass** | v2 pattern in discover: BA tells their view first (Step 1a), then agent scans codebase for evidence (Step 1b), then confronto compares the two (Step 1c). Prevents anchoring bias. |
| **AS-IS Localization** | v2 pattern in decompose: for each PBI, identify exactly which file/module/function/endpoint is affected in the current codebase. Flags: `[NOT LOCALIZED]`, `[GREENFIELD]`. |
| **BABOK** | Business Analysis Body of Knowledge, published by IIBA. OpenBA aligns to v3. |
| **BACCM** | Business Analysis Core Concept Model — 6 concepts (Change, Need, Solution, Stakeholder, Value, Context) applied to every artifact. |
| **Board** | Status overview of all active artifacts, generated by `/openba-trace`. Located at `01-status/board.md`. |
| **Business Capability Map (BCM)** | Strategic map of all capabilities a product/organization provides, organized into Areas and Capabilities. Created by `/openba-bcm`. |
| **Business Requirement** | Requirement at the organizational level, describing what the organization needs to achieve. Level: Business. |
| **Capability** | A specific thing the system or organization can do. Belongs to a Capability Area in the BCM. |
| **Capability Area** | A top-level grouping in the Business Capability Map (e.g., "Certificate Management", "Notification"). |
| **Confronto** | Italian for "comparison". The third step in the AS-IS Double Pass where BA view and codebase evidence are compared side by side. |
| **Coverage** | The degree to which a higher-level artifact has corresponding downstream artifacts. A Need is "Covered" when it has Requirements + Features + PBIs. |
| **Deferred Log** | Shared file (`00-context/deferred-log.md`) tracking items the BA consciously parked. Each item has a status: RESOLVE NOW, KEEP IN MIND, or PARK IT. |
| **Definition of Ready (DoR)** | 10-item checklist that a PBI must pass before entering a sprint. Validated by `/openba-groom`. |
| **Decomposition** | Breaking a higher-level artifact into more specific lower-level artifacts (Requirement → Features → PBIs). |
| **Elicitation** | The process of drawing out information from stakeholders using techniques (interviews, workshops, etc.). |
| **Exit Condition** | Agent-controlled rule that determines when a loop (Grill Me, Debate) can end. The BA cannot self-exit — the agent decides when criteria are met. |
| **Feature** | A coherent functional capability that groups related PBIs. Larger than a PBI, smaller than an epic. |
| **Functional Requirement** | Requirement describing what the system must do (behavior). Level: Functional. |
| **Gap Analysis** | Comparison between AS-IS (current state) and TO-BE (future state) to identify what's missing. |
| **Gherkin** | A structured format for acceptance criteria: Given [context], When [action], Then [outcome]. |
| **Grill Me Loop** | v2 pattern where the agent challenges the BA with probing questions, one at a time, until the exit condition is met. Used in discover, specify, and debate. |
| **Grooming** | The process of validating PBIs against DoR, checking INVEST, and scoring readiness. |
| **INVEST** | Quality heuristic for PBIs: Independent, Negotiable, Valuable, Estimable, Small, Testable. |
| **INVEST Pre-Gate** | v2 pattern in decompose: all 6 INVEST criteria must pass BEFORE the PBI file is written to disk. |
| **KEEP IN MIND** | Deferred Log status: item is relevant but not blocking; revisit when adjacent work is done. |
| **Need** | A business problem or opportunity that justifies change. The highest-level artifact in OpenBA. |
| **Non-Functional Requirement** | Requirement describing quality attributes (performance, security, availability). Level: Non-Functional. |
| **Orphan** | An artifact missing its expected upstream link (e.g., PBI with no Feature). |
| **PARK IT** | Deferred Log status: item is out of scope for now; revisit at a specified future date. |
| **PBI** | Product Backlog Item — sprint-sized unit of work with user story and Gherkin acceptance criteria. |
| **Pipeline** | The 11-skill sequential flow from init through status. |
| **Project Code** | 2-4 uppercase letters used as prefix in all artifact IDs (e.g., "CT" for CertTracker). |
| **Requirement** | A condition or capability that must be satisfied. Has 5 possible levels. |
| **RESOLVE NOW** | Deferred Log status: item is blocking and must be resolved before proceeding. |
| **Resume Mode** | v2 pattern: skills that support long sessions (discover, specify) save progress to a WIP file and can resume where they left off. |
| **Situation Analysis** | Assessment of AS-IS state, TO-BE state, and the gap between them. Produced by `/openba-discover`. |
| **Split Challenge Loop** | v2 pattern in decompose: agent proposes a split, challenges it, BA confirms, then writes. Prevents hasty decomposition. |
| **Stakeholder** | A person or group with a relationship to the change being analyzed. |
| **Stakeholder Requirement** | Requirement describing what users need to do or achieve. Level: Stakeholder. |
| **Traceability** | The ability to follow the chain from Need → Requirement → Feature → PBI (and back). |
| **Traceability Matrix** | Document showing all artifact links, coverage, orphans, and gaps. Generated by `/openba-trace`. |
| **Transition Requirement** | Requirement for migrating from current to future state. Level: Transition. |
| **User Story** | "As a [role] I want [capability] So that [value]" — the standard format for PBI statements. |
| **Validation** | Confirming an artifact is correct and real (e.g., stakeholder confirms a Need). |
| **WIP File** | Work-in-progress session file (e.g., `discovery-wip.md`, `specify-wip.md`) that tracks current session state for Resume Mode. |
