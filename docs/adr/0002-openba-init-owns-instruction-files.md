# openba-init owns AI-instruction-file generation, not the CLI

`openba setup` used to generate a stub `CLAUDE.md` / `AGENTS.md` / `.github/copilot-instructions.md` (skipped if the file already existed). The v2 `openba-init` skill now asks the user which AI platform they use and generates a richer, platform-specific instruction file itself when run inside the user's AI tool — and, like the CLI stub, refuses to overwrite an existing file. If the CLI kept generating its stub at setup time, `openba-init` would always find the file already present and never write its richer version. We removed instruction-file generation from the CLI (`setup.js`, `installer.js`) entirely: the CLI's job is installing skill files, and `openba-init` — which now has more context (it runs after init, inside the actual tool) — owns generating the project's instruction file.
