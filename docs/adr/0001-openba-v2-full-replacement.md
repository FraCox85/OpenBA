# OpenBA v2 fully replaces v1 — not additive

The upstream OpenBA framework shipped a v2 with a different artifact model (Need → Requirement → Feature → PBI, BABOK-aligned) and a renamed skill set (`openba-*`, 11 skills) that has no 1:1 mapping to the v1 skill set (`oba-*`, 14 skills, Epic → Feature → PBI model). We considered installing v2 skills alongside v1 so users could choose, but the two artifact models are incompatible in the same workspace and the upstream docs treat v2 as a straight succession, not a variant. We chose full replacement: v1 skills are retired from `openba-cli`, `openba-` becomes the canonical skill-id prefix (replacing the old `oba-` source naming and the oba-→openba- translation layer in the installer), and the package version bumps to 2.0.0. `openba update` detects a v1 config (skill ids the v2 registry doesn't recognize) and forces a wipe + re-setup instead of trying to reinstall retired ids.
